# 系统设置

## 账号与登录

- 默认是**开放模式**（本机免登录）。需要多人使用时，在「账号与登录」里创建管理员并**启用登录**。
- 角色：管理员（全权）、`viewer` 只读账号；危险操作（删除借用记录、数据维护等）需要管理员。
- 登录方式支持本地账号；`钉钉登录` 与 `外部对接验证` 为预留能力（默认关闭，需要时在「开发者选项」里开启）。

## 邮件通知（SMTP）

配置：SMTP 服务器地址、端口、SSL/TLS、账号、授权码、发件人、收件人（可多个，用逗号或空格分隔）。

常见配置：QQ 邮箱 `smtp.qq.com:465`（用授权码）；163 邮箱 `smtp.163.com:465`；企业邮箱一般是 `smtp.<域名>:465`。

两类自动提醒可单独开关：

| 类型 | 触发逻辑 |
| --- | --- |
| **周期提醒** | 按「提醒间隔」（每天 / 每 3 天 / … / 每 3 个月）发送一次**临期 / 过期 / 借用超期**汇总；每天在执行时刻检查，服务器启动时若当天应发却漏发会补发一次 |
| **到期档位提醒** | 对每个计量器具 / 药品，在距到期分别为所选提前天数（如 90 / 30 / 7 / 3 / 1 天）时各提醒一次；同一对象同一档位只提醒一次 |

内容模板可自定义（主题 / 开头 / 结尾 / 落款），支持占位符：`{实例名}`、`{单位}`、`{日期}`、`{时间}`、`{类型}`、`{数量}`、`{统计}`、`{明细}`、`{系统名}`、`{版本}`、`{面板地址}`。点 `👁 预览邮件效果` 可先看渲染结果（不会发送）。

### 手工补发

自动提醒漏了、或者想补发某一天的通知时用：

1. 勾选要补的类型（**周期汇总** / **档位到期**，可只补一种）。
2. 选择**归属日**（默认今天；也可选过去某一天）。
3. 点 `🔄 手工补发`。

行为说明：

- **忽略**“今天已发过 / 未到提醒间隔 / 未到执行时刻”这些限制，立即发送。
- 周期汇总按所选日期重放临期 / 过期 / 借用超期；档位到期按所选日期计算剩余天数，并且**忽略历史“已提醒档位”标记**（不会影响后续自动提醒）。
- 每次补发都会在下方「发送 / 漏发记录」里留档，触发方式显示为 **手工补发**。

## 品牌素材

- 可上传 **Logo** 与 **登录页背景图**（有格式、大小、分辨率限制，上传前会提示）。
- 设置后：侧栏 Logo、浏览器标题、登录页、**浏览器标签页图标**都会使用它（需先上传）。
- 清除后回落到版本特化配置或程序内置 Logo。

## 数据维护

| 功能 | 说明 |
| --- | --- |
| 💾 备份数据库 | 下载一致性快照（`VACUUM INTO`），可直接用于恢复 |
| 📦 导出全部数据 | 完整数据包 zip：数据库 + 自定义模板 + 品牌图片 + 版本特化配置 |
| 📥 导入全部数据 | 从数据包还原整套环境 |
| 🛠 从数据库文件恢复 | 直接选一个 `.db` 备份文件恢复；恢复前自动留存当前数据，失败整体回滚 |
| ⏱ 每日定时备份 | 每天定时生成 `auto_*.zip` 完整数据包，保留份数可配置 |
| 🧹 数据清理 / 日志 | 清理历史操作日志、邮件记录等 |

> ⚠️ **不要手工把备份文件拷进数据目录覆盖 `warehouse.db`**。数据库使用 WAL 日志，覆盖主库文件会留下不匹配的 `-wal`，导致数据库打不开。请一律用上面的恢复入口（恢复失败也能整体回滚）。

## 模板设置

- 单据（入库单 / 出库单 / 盘库表 / 清单表）的列顺序、列名、页眉页脚都能自定义，可下载 / 上传模板，也有内置模板可恢复默认。
- 模板保存在数据目录的 `templates/` 下，随数据包一起备份。

## 系统日志

记录用户操作与接口调用（可按等级筛选、设置保留天数），排查问题时会很有用。
