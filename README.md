# ThingsManager · 轻量仓库管理

**装完即用的仓库 / 库存管理系统**：单文件后端、零外部数据库、Windows 与 Linux 一键安装，
数据 100% 存在你自己的机器上。

> 这个项目的每一行代码都由 **AI 结对编程（Vibe Coding）** 写成——需求、品味与验收由人把关，
> 实现、重构、排错、打包、文档与 CI 流水线由 AI 执笔。它不是"AI 生成的 demo 片段"，
> 而是一套能直接装进生产环境的完整系统（详见文末「关于 Vibe Coding」）。

> 仓库：[GitHub](https://github.com/BH6AOV/ThingsManager) · [Gitee 镜像](https://gitee.com/BH6AOV/ThingsManager)

`Node.js ≥ 22.13` · `零外部数据库` · `零原生编译` · `无构建前端` · `AGPL-3.0-or-later`

## 它能做什么

| 模块 | 说明 |
| --- | --- |
| **仪表盘** | 商品数 / 在库 SN / 今日单据 / 低库存提醒，最近单据一览 |
| **出入库** | 逐行编辑入库单、出库单；数量商品填数量，SN 商品粘贴或扫码登记，出库勾选在库 SN |
| **盘库** | 数量商品填实盘数自动校正差异；SN 商品按盘亏 / 盘盈逐件核对；可导出空白盘点表 |
| **单据流水** | 单据留档与明细查看，随时重新导出 xlsx / PDF |
| **商品管理** | SKU 维护、分类、按 SKU 单独开关 SN 管理 |
| **库存与清单** | 实时库存查询，一键导出库存清单表（xlsx） |
| **SN 管理** | 全量序列号检索：在库 / 已出、出入库时间、归属单据 |
| **物资借用** | 借用登记与归还、到期提醒，可删除误录记录（管理员密码确认） |
| **跨库流转** | 出库单可直接推送给另一台实例，对方确认后自动生成入库单（含待办提醒） |
| **模板设置** | 四类单据模板的下载 / 上传覆盖 / 重置 / 效果预览 |
| **系统设置** | 单位抬头、默认经办与库位、数据目录迁移与备份、账号登录、互联服务 |

**几个好用的细节**

- **SN 序列号**：每个 SKU 可独立选择「数量管理」或「SN 管理」；同商品内 SN 唯一，重复入库会被拒绝；库存数量由在库 SN 自动统计。
- **多账号权限**：默认开放模式，随时可在设置里启用登录；管理员 / 普通用户 / 只读账号三级。
- **互联互通**：本机可对外提供只读查表接口，也可登记其它实例，查看对方在线状态与库存表预览。
- **单据三件套**：xlsx（走模板）/ PDF（A4 中文，带二维码）/ 二维码扫码入账（跨设备"扫单"）。
- **批量入库**：上传含 SKU 编码 + 数量（或 SN）列的表格，预览确认后直接生成入库单。
- **自定义模板**：内置模板不合口味可以整套替换，导出的单据就是你的格式。

> 金额、单价不是本系统的关注点：默认模板不含金额列，需要时自建模板即可。

## 安装

### Windows 10 / 11（推荐）

到 **[Releases](https://github.com/BH6AOV/ThingsManager/releases)** 页面下载（Gitee 镜像的[发布页](https://gitee.com/BH6AOV/ThingsManager/releases)同样可用）
`ThingsManager_<版本>_windows_AMD64.exe`（或 `_windows_ARM64.exe`），双击安装即可——**安装包已内嵌精简 Node 运行时，无需另装 Node.js、也无须数据库**。

安装后会注册为 Windows 服务（开机后台自启）+ 系统托盘常驻，桌面图标双击即打开管理面板。

### Linux 服务端

| 发行版 | 文件 | 安装 |
| --- | --- | --- |
| Debian / Ubuntu | `ThingsManager_<版本>_linux_AMD64.deb` | `sudo apt install ./文件.deb` |
| RHEL / CentOS / Fedora | `ThingsManager_<版本>_linux_AMD64.rpm` | `sudo rpm -ivh 文件.rpm` |
| 任意 Linux | `ThingsManager_<版本>_linux_AMD64.AppImage` | `chmod +x 文件.AppImage && ./文件.AppImage` |

（把 `AMD64` 换成 `ARM64` 即为 ARM 版本。）

- 安装为 systemd 服务：`systemctl status|start|stop|restart thingsmanager`，日志 `journalctl -u thingsmanager -f`。
- AppImage 免安装：数据默认在 `~/.local/share/ThingsManager`，端口用 `THM_PORT` 覆盖。

### 源码运行（开发 / 折腾）

```bash
npm ci --omit=dev      # 安装生产依赖（纯 JS，无需编译器）
node server.js         # 默认 http://127.0.0.1:3200
```

Windows 也可双击 `start.bat`。换端口：`PORT=8080 node server.js`。

| 环境变量 | 作用 |
| --- | --- |
| `THM_PORT` / `PORT` | 监听端口（默认 3200） |
| `THM_HOST` | 监听地址（默认 `0.0.0.0`；`127.0.0.1` 回环始终由程序兜底监听） |
| `THM_DATA` | 数据目录（覆盖程序目录下的 `data/`） |
| `THM_CONFIG` | 运行时配置文件路径（Linux 服务版用） |

浏览器打开 `http://<设备IP>:3200` 即可访问；同一局域网内多台设备都能用。

## 上手三分钟

1. 首次进入若是空库，会询问是否写入一套**演示数据**——想快速看看效果就选它，正式用选空白起步。
2. 「商品管理」建几个物资（编码 / 名称 / 型号 / 单位 / 存放位置），需要序列号管理的勾上 **SN 管理**。
3. 「出入库」做第一张单：选物资 → 填数量（或粘贴 SN）→ 保存；单据可导出 xlsx / PDF，也能出示二维码让手机扫码入账。
4. 想换个格式？到「模板设置」下载内置模板，改成你单位的样式再上传覆盖。

## 自定义单据模板（xlsx）

四类单据（入库单 / 出库单 / 盘库表 / 库存清单）都由 xlsx 模板驱动，规则很简单：

1. **明细标记**：某一行的首格写 `{{明细}}`，该行即明细起始行，其上一行作为表头行。
2. **列识别**：按表头关键词自动匹配（编码 / 名称 / 型号 / 单位 / 数量 / 账面数量 / 实盘数量 / 差异 / SN / 存放位置 / 备注…），列顺序随意。
3. **占位符**：`{{doc_no}}`、`{{date}}`、`{{party}}`、`{{operator}}`、`{{location}}`、`{{company}}`、`{{remark}}`、`{{total_qty}}` 等，中英写法都认。
4. 数据行会按明细条数自动扩展并复制行样式；明细区域**不要用横向合并单元格**。

在「模板设置」里下载内置模板，照着改最省事。

## 数据、备份与迁移

数据默认位置：

| 平台 | 数据目录 |
| --- | --- |
| Windows 安装版 | `%ProgramData%\ThingsManager` |
| Linux deb / rpm | `/var/lib/thingsmanager` |
| AppImage / 源码运行 | 程序目录下的 `data/`（或 `THM_DATA` 指定的目录） |

数据目录里就三样东西：`warehouse.db`（SQLite，WAL 模式）、`templates/`（当前生效的模板）、`brand/`（上传的 Logo 与背景图）。

- **备份**：系统设置里可一键导出数据包（数据库一致性快照 + 模板 + 品牌），也可以直接拷 `data/` 目录。
- **迁移**：系统设置 → 数据目录，选一个新目录即可整体搬迁（会校验目标为空、复制完成后提示重启生效）。
- 数据库就是一个文件，随手复制就是备份，不怕厂商跑路。

## 常见问题

**手机扫码提示需要 HTTPS？** 浏览器只允许在 HTTPS 或 localhost 下调用摄像头。局域网 HTTP 访问时，用「拍照 / 上传图片」扫码即可（调系统相机，效果一样）；或给站点套一层 HTTPS 反代。

**80 端口 / 端口冲突？** 本程序默认用 3200（避开与系统服务的冲突），可在「系统设置 → 桌面 / 网络」里改；保存后重启程序生效。

**局域网其它设备访问不了？** 检查系统防火墙是否放行该端口（Windows 安装版会自动加防火墙规则），以及是否把监听地址设成了 `127.0.0.1`。

**换电脑 / 重装系统会丢数据吗？** 数据在数据目录里，与程序位置无关；装新版本、覆盖升级都不会动它（升级只替换程序文件）。

## 关于 Vibe Coding

这个项目是一次**完整的 Vibe Coding 实践**：由人提出需求、把关方向与验收，AI 负责设计、编码、排错、
测试与打包——从第一行 `server.js` 到 Windows 安装器、Linux 服务端三件套、跨平台 CI 流水线，
全部在一来一回的对话中完成。

它做到了什么：

- **能装进生产**：Windows 侧是带服务注册、托盘守护、开机自启、数据目录迁移的正式安装包；Linux 侧是带 systemd 常驻与自检脚本的 deb / rpm / AppImage。
- **有工程约束**：单文件后端 + 无构建前端（降低维护面）、零外部数据库与零原生编译（降低部署面）、数据目录与程序目录分离（升级不丢数据）。
- **有自动化保障**：打一个 `v*` 标签，CI 自动构建全平台产物、生成校验清单并发布 Release。
- **功能不打折**：SN 追踪、盘库校正、借用归还、二维码扫码入账、PDF 导出、多账号权限、多实例互联与跨库流转，样样能用。

写代码的方式变了，交付标准没有变——**它首先是能用的软件，其次才是 AI 的产物**。
